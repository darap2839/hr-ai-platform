## Цель и порядок работы

Главная функция — самостоятельно находить и ранжировать подходящих кандидатов
из всей загруженной базы резюме по потребности предприятия радиоэлектронной
отрасли, с семантическим анализом и проверяемым обоснованием. Работа локальная,
бюджет нулевой, внешние данные рынка труда не используются.

Методика — итерационная V-модель: требование → решение → проверка → доказательство.
Восстановленный порядок этапов: диагностика; требования и критерии приёмки;
достоверность входных данных; отраслевая модель; контрольный набор; извлечение
Qwen; embeddings и Qdrant; ранжирование и объяснения; интеграция рабочего
процесса; качество, устойчивость, безопасность и CI. Даты этапам не назначаются.

После каждого этапа: отдельные коммиты, проверка Actions, мини-вывод владельцу,
приёмка перед следующим этапом. Изменения этапа оформляются веткой и PR в master.

## Локализация причины отсутствующего learners

Предоставленная пользователем структура raft_state.json содержит ключ
`state.conf_state.learnersdoker: []` вместо `learners: []`. Остальные показанные
поля conf_state присутствуют. Непосредственная причина ошибки десериализации
установлена: неверное имя ключа. Происхождение опечатки не установлено;
автоматически приписывать её обновлению Qdrant или файловой системе нельзя.

Предлагаемое восстановление: остановить существующий Qdrant, скопировать его
хранилище в отдельный резервный каталог, заменить только имя JSON-ключа
learnersdoker на learners с сохранением остальных байтов/числовых значений,
записать UTF-8 без BOM и запустить существующий контейнер без загрузки образа.
После запуска проверить журнал и HTTP /healthz. Исправление на пользовательском
компьютере ещё не выполнено/не подтверждено; D-10 остаётся открытым.

## Фактические сведения о теме с локального стенда

Пользователь предоставил: Keycloak 26.7.1/JVM 21.0.12; SELECT realm для platform
показывает пустой login_theme; Get-ChildItem keycloak/themes не выводит файлов.

PowerShell внутри IDE). Изменения настроек этими командами не выполнялись.

По исходникам Keycloak 26.7.1 DefaultThemeSelectorProvider сначала рассматривает
client attribute login_theme, затем настройку realm, затем тему по умолчанию.
