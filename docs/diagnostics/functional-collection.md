# Функциональная диагностика существующего локального стенда

Инструменты: `scripts/functional-diagnostics.py` и
`scripts/run-functional-diagnostics.ps1`. PowerShell 5.1/7 запускает Python-код
в существующем backend-контейнере через stdin. Ничего не устанавливается.
Путь API: backend-контейнер → nginx → backend. Проверка не зависит от Windows
порта 80 и не заменяет испытания браузера.

Запуск из каталога репозитория:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-functional-diagnostics.ps1 -TestAIOutage
```

Скрипты, скачанные отдельно, запускаются с явными `-ProjectDirectory` и
`-RunnerPath`. Без `-TestAIOutage` выполняются только функциональные проверки.
С этим параметром ранее работающий AI Engine временно останавливается;
в finally выполняется start и проверяется восстановление /health и генерации.
На это время пользователи не смогут обращаться к модели. Готовность после
перезапуска ожидается до 120 секунд, генерация — до 135 секунд. Если процесс
PowerShell принудительно закрыт или восстановление завершилось ошибкой,
проверить `docker compose --profile ai ps -a`; запустить модель командой
`docker compose --profile ai start ai-engine`.

## Покрытие

- VAC: валидация зарплаты, создание/чтение/изменение/закрытие/открытие/удаление.
- CAN: создание/чтение/изменение/удаление.
- APP: создание отклика, текущий анализ, стадия, вопросы, проверка каскадной очистки.
- DOC: TXT preview/upload, байтовое чтение файла из MinIO, редактирование,
  история версий, корзина, восстановление и окончательная очистка.
- AUTH: ожидаемый отказ 401/403 при чтении собственных синтетических записей
  без токена. HTTP 200 считается дефектом защиты, а не успехом авторизации.
- ORG: чтение подразделений; NOT: наличие уведомлений своих сущностей, отметка
  прочитанным и удаление только этих уведомлений.
- SYS/AI: /health и обращение к БД при остановленной модели, ожидаемый 503
  для chat, реальная генерация после перезапуска.

Для анализа отклика проверяется воспроизводимость действующего строкового
алгоритма на одинаковом навыке PCB; это не испытание семантической релевантности.
Браузерная сессия Keycloak/обновление токена/выход, доставка SSE и качество
поиска по всем резюме остаются отдельными проверками со статусом blocked.
Проверки не обходят защиту API и не собирают учётные данные. Если API начнёт
требовать токен, анонимные CRUD-пробы закономерно перестанут проходить.

## Синтетические данные и очистка

Создаются только записи с уникальным префиксом HRDIAG. Перед удалением
повторно проверяются точные ID и имя/заголовок с префиксом текущего прогона.
Неопределённый ответ записи (например, 500 после возможного commit) отмечается
как CLEANUP-UNCERTAIN с префиксом для отдельного разбора. Очистка всех записей,
всех уведомлений или существующих коллекций Qdrant не выполняется. Записи могут
остаться при ошибке API/разрыве соединения/прерывании: это фиксируется в отчёте.
Синтетические уведомления не рассылаются через внешние сообщения.

ZIP в TEMP содержит результаты фаз и статусы восстановления. Ответы API,
резюме, токены, пароли и исходные логи не сохраняются. Архив приложить в чат.

Actions `Stage 1: Functional diagnostic tool` проверяет сам инструмент на
подменах HTTP/Docker, включая запрет удаления чужих данных и finally при ошибке.
Зелёный CI инструмента не является доказательством прохождения приложения:
результаты реальных API будут получены только из локального ZIP.
