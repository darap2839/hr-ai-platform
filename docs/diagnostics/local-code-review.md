# Разбор локального архива hr-ai-local-code.zip

Источник: архив владельца от 20.11.2026. Проверяется совместимость с веткой
`test/stage-1-diagnostics`. Скомпилированные `__pycache__/*.pyc` не исполнялись
и не включались в рабочий код. Исходный ZIP не изменён.

## Результат

Архив содержит отдельный незавершённый прототип RAG, тесты демо/кандидатов и
генератор вакансий на правилах. Это не установленный семантический поиск по
резюме. Подключение прототипа к действующим коллекциям не выполнялось.

| Область | Установленная причина | Действие в этапе 1 |
|---|---|---|
| Demo | API dashboard вызывает `seed_demo`, но сервис содержит только `seed_demo_data`; его внутренние вызовы репозиториев тоже устарели | Восстановлен метод, записи создаются одной транзакцией, повторный последовательный вызов не создаёт дубликаты; прежнее имя сохранено |
| Candidate | Три теста создания/повторного email/списка совместимы | Добавлены в версионный набор, пройдены |
| Documents | `.value` отсутствует у SQLAlchemy True_/False_ | Assertion заменён проверкой реальных строк активных/удалённых документов через SQLite; поведение API не менялось |
| ORG | Старые тесты ожидают дерево вместо согласованного справочника | Проверяются карточки, поиск, отдел, пустая выдача, контакты и статус |
| ORG modal | Клик карточки менял state, но окно отсутствовало в основном return; вызов окна ошибочно находился внутри самого окна с недоступными переменными | Вызов перенесён в страницу, четыре теста справочника пройдены |
| MinIO | Конструктор делал сетевой bucket_exists при импорте модуля | Проверка/создание bucket перенесены к загрузке файла; offline collection не требует MinIO; четыре регрессионные проверки |

## RAG: блокирующие расхождения (D-19 остаётся открыт)

1. Нет `KnowledgeDocumentModel`, его миграции и экспорта из app.models.
   Имеющийся `DocumentModel` использует `content_text`, имеет архив/корзину,
   авторство и права; у прототипа поля `content`, `source`, `entity_type/id`.
   Подмена одного класса alias-ом не сохраняет контракт. Решение должно
   определять источник текста и связь с версиями существующих документов,
   а не вводить дублирующий архив без требования.
2. Нет `DocumentType` в app.models и экспортов `KnowledgeDocument*` в app.schemas.
   Типы прототипа (`resume`, `regulation`, `instruction`, `other`) не совпадают
   с текущим Literal (`policy`, `procedure`, `role_profile`, `template`, `guide`).
3. В Settings отсутствуют `embedding_dimension`, `qdrant_url` и имена трёх
   коллекций. Прямой вызов get_embedder воспроизвёл AttributeError.
4. `rag/__init__.py` немедленно импортирует service, тот создаёт глобальный
   RAGService. Поэтому даже независимый импорт chunker/embeddings тащит БД,
   схемы, настройки и клиент. Это объясняет четыре collection errors. В отдельной временной копии текущего
   app с наложенными исходниками архива pytest --collect-only воспроизвёл ровно
   эти четыре ошибки, без изменения рабочей версии.
5. VectorStore.ensure_collection при другой размерности автоматически удаляет
   коллекцию целиком. Такую операцию нельзя выполнять как побочный эффект ingest;
   несовместимость должна прерывать запись, миграция индекса проектируется отдельно.
6. Ingest коммитит БД до успешной записи Qdrant; delete сначала коммитит удаление
   БД; reindex сначала удаляет старые векторы. Нет гарантии согласованного
   состояния при отказе второй системы. Нужны явное состояние индексации и
   повторяемое восстановление, а также испытания отказа и восстановления.
7. Не проверяется равенство количества chunks/vectors: zip молча отбрасывает
   лишние элементы. Нет регрессионных тестов самого VectorStore.
8. Прототип вызывает QdrantClient.search. В локально установленном при разборе
   qdrant-client 1.20.0 этого метода нет (проверено через hasattr); нижняя граница
   requirements не обеспечивает совместимость с любым новым выпуском.
9. Получение текста из резюме, автоматическая индексация всех кандидатов,
   удаление устаревших версий, применение прав/архива при поиске и ранжирование
   кандидатов с агрегацией чанков не подключены этим архивом.

Ни один из этих пунктов не исправлен фиктивным экспортом или автоматическим
созданием новых таблиц. Полноценная интеграция относится к согласованию данных
и этапам индексации/поиска; диагностика сохраняет причины непрохождения.

## Проверенные ограничения качества

Исходный embeddings.py загружен отдельно через importlib, без выполнения
rag/__init__.py. Это проверка чистого алгоритма, не успешный импорт RAG-пакета.
HashEmbedder(256) дал cosine:

| Тексты | Сходство |
|---|---:|
| «Python FastAPI» / «FastAPI Python» | 1.0 |
| «разработка печатных плат» / «проектирование PCB» | 0.0 |

Это два контрольных примера, не оценка качества на корпусе. Hashing trick
сопоставляет слова и их коллизии; тест перестановки одинаковых слов не доказывает
семантическую близость. Комментарий о будущем OpenAI embeddings не является
согласованным планом: проект должен работать локально, без платного API.

Chunker: строка из 1000 символов x, max_chars=100, overlap_chars=20, породила
22 чанка с длинами 100, затем чередованием 102/20, последний 122. Заданный
максимум нарушен; переносы и перекрытие требуют граничных тестов. Не тестировать
невалидные размеры без ограничений времени: в исходнике нет валидации параметров.

Генератор `utils/vacancyGenerator.js` заполняет шаблоны по ролям/словам,
не обращается к модели и не доказывает семантическое сопоставление. Эти
неотслеживаемые утилиты не добавлялись в runtime ради увеличения числа тестов.

## Проверки исправленной рабочей версии

Python 3.12, pytest 7.4.3; локальный изолированный venv с доступом к базовым
пакетам среды. Зависимости не зафиксированы lock-файлом, версия отличается от
Python 3.13 владельца. Полный backend suite: **83 passed**, без исключения
MinIO-модулей и без collection errors. Операции хранения файлов в unit-тестах
заменены mocks; БД — SQLite, это не интеграция с настоящим MinIO/PostgreSQL.
Frontend: **36 passed** в восьми файлах, production build успешен с прежним
предупреждением о размере JS chunk. Незавершённые RAG-модули не входили в эти
наборы и не объявляются пройденными. Подтверждение GitHub Actions записывается
отдельно после завершения запуска.

До исправления: два архивных demo tests failed; новый тест открытия карточки
справочника failed, остальные три прошли; попытка импорта MinIO с запрещённым
bucket_exists воспроизвела сетевой вызов при импорте. После исправления также
пройдены сохранение существующих записей, откат demo при ошибке commit,
контракт API handler и создание bucket перед первой записью.

CI изменён на полные наборы backend/frontend перед публикацией образов.
Из диагностического workflow удалён обязательный старт MinIO для unit-тестов:
он не нужен после удаления I/O при импорте. Реальная проверка MinIO остаётся
отдельной live-проверкой, а миграции PostgreSQL остаются отдельным CI job.
